# Generation service

Java calls `POST /internal/generation/stream` with `Authorization: Bearer <INTERNAL_SERVICE_TOKEN>` and the frozen request `{runId, kind, projectId, documentVersionIds, prompt, history: [{role, content}], titles: {versionId: title}}`. Response is newline-delimited canonical RunEvent JSON, sequence starts at 1. Java remains responsible for scope authorization, persisted events, cancellation state, and revalidating sources before completion. Disconnect cancellation stops further generation consumption; a blocked provider read may take until the remaining 120/300-second deadline to unwind. Provider cancellation cannot guarantee billing stops.

`GENERATION_MODE=demo` is the default and visibly labels deterministic excerpts. `DEMO_CHUNK_DELAY_MS` optionally paces each 64-character demo chunk (default 0, clamped to 0–1000 milliseconds), for browser cancellation/reconnection tests. It does not affect the real adapter.

`GENERATION_MODE=openai-compatible` requires all of `OPENAI_BASE_URL` (API root, normally ending in `/v1`), `OPENAI_MODEL`, and `OPENAI_API_KEY` from server environment. No fallback occurs for missing real configuration. The adapter uses POST `/chat/completions`, `stream=true`, max_tokens=2000 for answers / 6000 for reports, and the server deadline. Partial, malformed, missing citations or truncated provider output fails the run. Connections have a five-second connect limit; stream reads use the remaining total deadline, with an independent socket shutdown at that deadline to stop trickling partial lines. Redirects are rejected before any credential forwarding. Streaming failures are not transparently retried. Upstream error bodies are not returned or logged. Real provider/model quality acceptance is deferred by user; local HTTP adapter tests do not represent real model quality.

Retrieval is imported lazily from `retrieval.retrieve` and uses only Java's frozen project and version scope. Empty evidence never calls a provider. Citation membership proves provenance exists, not semantic support.

Reports use a lazy `generation.report.generate_report(evidence, provider, prompt, allowed_version_ids, titles, deadline)` async seam provided by the reports branch. The route adapts the shared provider to its async interface and returns canonical delta/citation/completed events. Without that module it returns REPORT_NOT_AVAILABLE. Report completion persistence and draft creation belong to Java's report seam.
