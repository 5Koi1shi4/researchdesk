# Java reports and exports

Reports API owns immutable history and exports; generation owns `/api/runs`.

The lifecycle owner must call the proxied Spring `ReportService.completeDraft(projectId, ownerId, runId, title, markdown, canonicalCandidates, allowedVersionIds, demo)` only after validating its run attempt/fence and before committing completion. It rechecks project ownership, locks READY source document rows for the transaction, canonicalizes every citation through a narrowly granted database function, and persists only stable `[[cite:<chunk UUID>]]` markers actually present in Markdown. The same run completion returns its original draft; a different run always creates another report. This branch supplies the seam; lifecycle wiring is a generation dependency, so generated drafts are not exposed through a competing run route.

Create `/api/projects/{projectId}/reports` with `{title,markdown}` produces a manual version with no citations. List that collection; GET `/api/reports/{id}` supplies report metadata; GET its `/versions` and `/versions/{number}` supplies immutable history. POST `/versions` with `{baseVersion,markdown}` uses an atomic compare-and-swap and returns 409 VERSION_CONFLICT when another save wins. POST `/copies` with `{version,markdown}` preserves a conflicting edit as another draft. Create, save and copy return 201 ReportVersion. Titles are limited to 200 characters; Markdown to 200000 characters. Citation removal simply removes that citation from the new immutable snapshot. Unknown or malformed markers fail validation. Historical source snapshots remain persisted, while every public version response replaces deleted excerpts with null and availability DELETED.

POST `/api/reports/{id}/exports` with `{version,format}` returns 202 ReportExport. GET `/exports/{exportId}` polls its durable state. GET `/exports/{exportId}/download` authorizes ownership before private object reads; it returns an attachment with no-store and nosniff. Report edits never change the requested export version. If a source available at rendering is later deleted, the previous artifact is denied with 409 EXPORT_SOURCE_CHANGED; a new export carries the current deleted-source status.

A database-backed dispatcher atomically leases one job, fences attempts, and recovers expired leases. Transient failures receive at most three retries (four total attempts), deferred by 2, 4 and 8 seconds; permanent errors fail immediately. Rendering has a deadline covering request serialization, headers and the complete response body. EXPORT_RENDER_TIMEOUT_MS defaults to 90000 and accepts only 1–90000 milliseconds, so runtime configuration can tighten the ninety-second limit. The asynchronous body subscriber cancels responses above twenty MiB, and timeout/interruption cancels both the HTTP future and body subscription. Each attempt writes a distinct private key and publishes the object pointer only by current-fence CAS. Source rows are locked and availability rechecked in the publication transaction. Storage cleanup intent survives failed/stale writes with the existing one-hour not_before default. A dedicated database session holds the same hashtextextended(object_key,0) advisory lock used by the cleanup worker from durable intent insertion through private object write and fenced publication; the lock is released before the session returns to the pool. The existing ingestion cleanup worker processes orphan keys. The export scheduler is durable and independent of request threads.

The Python adapter calls `${AI_INTERNAL_URL:http://ai:8000}/internal/reports/export`, authenticates with `Authorization: Bearer ${INTERNAL_SERVICE_TOKEN}`, and sends `{markdown,citations,format}`. Redirects are disabled. Python returns raw Markdown or PDF bytes. Runtime must configure both AI_INTERNAL_URL and matching INTERNAL_SERVICE_TOKEN; browsers receive neither credentials nor the internal renderer URL. ObjectStorage.put uses the existing private bucket; authorized reads are proxied by ExportStorage rather than public/presigned URLs.

Tests: ReportMarkerTest covers stable markers and invalid input; ReportVersionIT uses real HTTP and PostgreSQL to verify history, CAS race, conflicts, copies and owner scope; ReportDraftIT uses the real business role on isolated loopback PostgreSQL15484 and tests canonical completion, per-run idempotence, distinct runs, foreign/unauthorized sources and deleted redaction; ExportIT uses real HTTP, renderer and private object storage to test fixed historical content and owner restrictions. The parent integration agent records exact Maven results and isolated runtime evidence.
