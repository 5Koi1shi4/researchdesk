## 1. 定位与目标

面向秋招全栈 AI 应用开发岗位的完整作品。用户创建研究项目，导入资料，通过带引用的问答理解材料，生成可编辑、可导出的研究报告。

延续既有 Java 后端、校园 AI 客服和 SentinelOps 项目的工程经验，本项目重点增加文档交互、流式体验、报告编辑和可量化的检索生成评测。历史项目作为经验参考，不修改其代码，也不共享其运行数据库。

核心演示流程：注册登录 → 创建项目 → 上传资料 → 查看解析结果 → 研究问答 → 点击引用定位原文 → 生成报告 → 人工修改 → 保存版本 → 导出。

交付物：独立代码仓库、可运行前后端、Compose 配置、演示资料、自动化验收证据、AI 评测结果、架构及技术取舍说明、面试讲解材料。

## 2. 首版范围

支持含可提取文字的 PDF 与 UTF-8 Markdown；不支持扫描件 OCR、联网搜索、多人实时协作、计费和任意工具执行。每个项目归属一个用户，首版不提供项目分享或协作者角色。

报告支持 Markdown 和 PDF 导出。界面中文优先，能够处理中文及英文资料。移动端以可用为目标，桌面端作为主要研究场景。

工程实现前选择并验证实际依赖版本，锁定到仓库，不以历史项目文档中的版本号作为兼容性依据。

## 3. 架构与部署

| 单元 | 职责 |
| --- | --- |
| React + TypeScript | 项目与资料管理、任务进度、流式问答、原文定位、报告编辑 |
| Java Spring Boot | 身份认证、所有权校验、业务数据、任务状态机、重试、会话、报告版本、用量记录 |
| Python AI 服务 | 文档解析与分块、检索与重排、模型调用、回答及报告生成、AI 评测 |
| PostgreSQL + pgvector | 业务数据及文档检索数据；以不同 schema 和账号隔离写权限 |
| MinIO | 原始文件和导出文件，私有存储 |
| Redis | 异步任务传输；不作为任务最终状态来源 |

Java 采用模块化单体，Python 为独立内部服务。首版两个后端部署单元，使用 Docker Compose 运行前端、后端及基础设施。生产入口为同源 HTTPS 反向代理；数据库、队列、对象存储管理端及 Python 不面向公网。

浏览器只通过 Java API 访问业务与 AI 能力。Python 仅接受经服务身份认证的内部调用，任务附带经 Java 校验的项目和资料范围。普通最终用户没有数据库、对象存储或模型供应商凭据。

Java 独占业务 schema 的写权限；Python 只能写检索 schema，并经内部接口回报任务结果。两个服务不通过修改对方业务表进行通信。

## 4. 页面与交互

### 4.1 项目首页

注册、登录、登出，创建项目，查看最近项目及研究目标。用户名使用邮箱形式，但首版不提供邮件投递、邮箱验证或密码找回；界面不得声称邮箱已验证。密码使用成熟密码哈希实现，登录限速，不记录密码。

采用服务端会话与 HttpOnly Cookie；生产使用 Secure，写操作进行 CSRF 防护。会话失效引导登录，不在浏览器持久存储访问令牌。

### 4.2 资料管理

上传、查看文件信息、解析状态、失败原因、重试和删除。初始默认限制为单文件 20 MiB、PDF 200 页、每项目 50 份资料，并允许部署配置收紧；在开始昂贵解析前尽可能校验。

状态由服务端提供，刷新后恢复。区分格式不支持、无可提取文本、加密文件、解析失败及服务暂不可用，向用户显示对应操作。解析完成前不能将文件当作可检索资料。

### 4.3 研究工作台

桌面为资料列表、问答区域、原文证据三栏；窄屏切换为可切换的单栏区域。支持多轮会话、限定本轮资料范围、流式回答、停止生成、错误后重新发起。

PDF 引用定位页码并展示相关摘录；首版不保证逐字坐标高亮。Markdown 引用定位标题及段落。保留可见焦点、控件标签和键盘路径；流式更新不频繁打断屏幕阅读器，也不在用户回看历史时强制滚动。

### 4.4 报告编辑器

根据研究目标和选定资料生成带引用草稿，支持 Markdown 编辑与预览、显式保存、历史版本查看、Markdown/PDF 导出。离开未保存页面时提示。

每次重新生成创建独立草稿，不覆盖人工内容。保存携带基础版本号；多标签页冲突返回明确提示，允许保留副本，不静默覆盖。PDF 导出支持中文字体并保留引用附录。

## 5. 数据对象与约束

- User、Session：用户和登录会话。
- Project：所有者、标题、研究目标与时间。
- Document、DocumentVersion：项目归属、内容摘要、对象键、解析版本、生命周期。
- IngestionTask、TaskAttempt：任务、尝试次数、租约、状态和可展示错误。
- Chunk：稳定片段 ID、文档版本、页码或段落位置、正文及向量。
- Conversation、Message、GenerationRun：会话、消息、资料范围快照、生成状态。
- Citation：已验证片段及来源位置，引用与消息或报告版本绑定。
- Report、ReportVersion、ExportTask：报告、不可变已保存版本及导出任务。
- UsageRecord、EvaluationRun：模型用量、耗时及离线评测记录。

每次访问由服务端沿资源关系验证项目所有权，不信任客户端用户 ID。不存在和无权访问的资源返回相同的 404。UUID 不是授权机制。

同项目内相同内容摘要的文件返回已有资料记录，跨项目不做可见去重。检索按项目及有效文档版本过滤，不在返回结果后才进行权限筛选。

## 6. 文档处理与可靠任务

上传文件 → Java 校验并存入私有对象存储 → 在业务事务内创建资料、任务和 Outbox 事件 → 分发到 Redis → Python 领取任务 → 解析、分块、嵌入 → 发布检索版本 → 回报 Java → 资料进入 READY。

业务任务状态为 QUEUED、RUNNING、SUCCEEDED、FAILED、CANCELLED。文档状态为 PROCESSING、READY、FAILED、DELETING、DELETED。Python 的进度与完成回报必须包含任务尝试标识及租约代次，过期执行者不能覆盖当前结果。

队列按至少一次投递设计。文档版本、解析配置版本及片段序号形成幂等身份；只有完整有效的一组片段才能发布，部分入库不能变为可检索。失败重试不创建第二份有效索引。

暂时性故障最多自动重试 3 次，使用退避；格式错误和无文本等永久错误不自动重试。达到上限后用户可显式创建新尝试。租约超时任务由恢复流程重新处理；Java 数据库是任务真相，Redis 丢失可由未完成记录恢复分发。

删除资料先在 Java 标记不可用，后异步清理原文及向量。新检索立即排除该资料；在途生成在最终保存前再次检查引用资料有效性，若已删除则终止并提示重试。历史引用显示“来源已删除”，不再提供原文或摘录；已生成答案或报告正文保留，并在删除说明中明确该行为。

## 7. 检索与生成

首版建立向量检索基线，再与加入关键词检索、融合排序及重排的方案对比，根据固定评测结果选择默认路径。初始检索候选上限 20 段、最终上下文上限 8 段，配置调整必须记录在评测版本中。

多轮问答只使用当前会话的有界历史，不将历史模型回答当作证据。资料范围由用户选择和 Java 授权共同确定，模型不能扩大范围。

模型得到带稳定 ID 的检索片段，生成答案及引用标记。服务端验证引用只指向本次有效检索集合，并映射成可点击位置。引用 ID 有效只证明来源存在，不等同于结论被证据支持，语义支持程度由评测单独衡量。

未检索到足够证据时返回资料不足提示；资料之间有冲突时保留冲突及各自来源。文档内容视为不可信数据，不能作为修改系统规则、权限或调用外部工具的指令。

回答使用流式草稿，完成引用验证后才标记为完成；停止或故障留下明确的未完成状态。报告也按同样的来源约束生成，不直接把历史聊天内容当作有据可查的事实。

模型供应商通过适配器接入；密钥仅在服务端。提供确定性替身用于无密钥演示和故障测试，UI 明确标识演示模式；真实模型评测单独执行，不用替身成绩代表 AI 效果。

## 8. API 与流式契约

浏览器入口统一为 `/api`，按 auth、projects、documents、tasks、conversations、runs、reports 分组。具体字段与 OpenAPI 在实施计划中固定，两端从契约校验兼容性。

生成采用“POST 创建运行 + GET SSE 订阅运行事件 + POST 取消运行”。事件包含递增序号，类型至少覆盖 started、delta、citation、completed、failed、cancelled。状态与有界事件记录持久化，客户端可带 Last-Event-ID 恢复；过期事件窗口通过读取完整运行快照恢复，不自动重复模型调用。

Java 验证流订阅权限并转发 Python 生成事件，浏览器不接触 Python 地址。取消会标记业务运行并尽力中止供应商请求；迟到事件不能将已取消运行改为完成。不能承诺取消后供应商立即停止计费。

错误响应使用稳定业务码、用户可行动说明与 requestId；不返回供应商原始错误体、内部堆栈、密钥或对象存储路径。401 引导登录，409 表示版本冲突，413 表示超限，429 表示配额或并发限制，503 表示暂时不可用。

默认每用户同时运行 2 个生成任务，问答总时限 120 秒、报告生成总时限 300 秒。流开始后失败不透明重试，避免重复内容和重复费用。默认模型输出上限为问答 2,000 tokens、报告 6,000 tokens，并允许按供应商能力收紧。

## 9. 安全与观测

校验文件类型、大小和解析资源预算；解析器在受限进程中运行，Markdown 禁止原始 HTML 和自动远程资源抓取。预览与模型输出经过安全渲染，报告 PDF 导出不允许任意网络或本地文件读取。

原文、问题和报告会按用途发送给配置的模型服务，上传及模型设置界面明确说明；日志不记录完整原文、提示词、回答、认证信息或密钥。

通过 requestId、taskId、runId 串联前后端及 Python。记录队列等待、解析耗时、检索耗时、首 token 延迟、总生成时长、失败类别、模型 token 用量。供应商没有返回的用量标为未知，成本估算展示价格配置日期，不冒充实际账单。

## 10. 测试与验收

### 10.1 前端

组件测试覆盖任务状态、流事件去重与恢复、引用跳转、报告未保存提醒及版本冲突。真实浏览器端到端流程覆盖注册登录、上传、问答、引用、报告编辑及导出，同时检查桌面和窄屏、键盘操作及错误恢复。

### 10.2 后端与基础设施

集成测试使用真实 PostgreSQL/pgvector、Redis 和对象存储，验证越权隔离、事务与 Outbox、重复投递、租约失效、worker 崩溃恢复、删除与在途生成竞态、报告版本冲突。验证队列中断、模型超时和无效文档不会变成假成功。

浏览器验收访问实际构建的前端及 Java/Python 链路；供应商可用可控替身注入故障，但报告中必须注明替身边界。另运行真实模型流程并记录独立结果。

### 10.3 AI 评测

使用允许再分发的演示资料建立初始 60 题数据集：单资料事实 20、多资料归纳或比较 15、证据不足 10、资料冲突 5、提示注入及越权诱导 10。每题包含资料范围、期望事实或行为、标准来源及题型。

固定划分 40 题开发集和 20 题保留集；调参只使用开发集。记录数据、切分、模型、嵌入、提示词及检索配置版本，对比向量基线与改进方案。

记录 Recall@5、引用语义支持准确率、关键结论引用覆盖率、无依据问题拒答表现、回答任务完成度、延迟及用量。安全授权验证使用确定性测试，不能仅靠模型评分。引用语义与报告质量采用人工标注规则，可辅以模型评分但不能以其作为唯一证据。

指标阈值在评测集与评分规则审定后、查看保留集结果前冻结，随评测协议提交。未冻结阈值和完成真实模型评测前不得宣称 AI 质量验收通过；设计阶段不虚构成绩。
